Trying to figure out how a task got to its current state usually meant paging through audit logs and cross-referencing timestamps yourself. That is gone.

Task details now have an activity tab that lists field-level changes newest-first. Each entry shows which field changed and who made the edit, so you can see the path a task took without jumping elsewhere. The same list is available from GraphQL, MCP, the CLI, and n8n, so the history shows up wherever you already work.

When a task is the record of who did what inside an organization, an edit trail is not a nicety. It is how you answer "why did this change" in a governance review. Now you can, in one place.
